# Security policy

## Поддерживаемая конфигурация

Поддерживаются актуальные Debian 12/13 на `amd64` и `arm64`, текущий стабильный Caddy, Docker CE и автоматически проверяемый `remnawave/node:latest`. Изменённые вручную firewall/Caddy/Compose-файлы не входят в гарантированную конфигурацию.

## Свойства, которые должны сохраняться

- TCP 22 доступен только панели и административному allowlist.
- TCP 2222 доступен только единственному IP панели.
- Caddy TLS 8443 слушает только loopback.
- Публично разрешены только TCP 80/443 и UDP 443.
- Проект не выполняет глобальный `flush ruleset` и не удаляет таблицы Node Plugins.
- Секрет Node хранится в root-only `node.env` и не печатается установщиком.
- REALITY private key не попадает в обычный stdout и показывается только явной TTY-командой.
- Hysteria private key хранится с mode `0600`.
- Caddy admin API отключён; root не читает Caddy-owned certificate paths напрямую.
- Firewall становится постоянным только после новой проверенной SSH-сессии и явного `yes`.
- Обновление Node откатывается при явной потере работоспособности.

## Не является гарантией

Проект не обещает неуязвимость, анонимность, обход конкретного DPI, отсутствие блокировки IP или защиту от volumetric DDoS. nftables не может определить намерение удалённой стороны до протокольного обмена, а публичные порты по определению достижимы. Защита от DDoS уровня канала должна предоставляться хостером/upstream. Политика автоматического `remnawave/node:latest` доверяет publisher/registry; rollback проверяет доступность, а не доброкачественность образа.

## Сообщение об уязвимости

Не публикуйте рабочие домены, IP, `SECRET_KEY`, REALITY private keys или Hysteria auth в issue. Передайте владельцу репозитория минимальный воспроизводимый отчёт приватным каналом GitHub Security Advisories после публикации проекта.
